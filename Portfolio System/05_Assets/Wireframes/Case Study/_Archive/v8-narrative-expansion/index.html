Context

Ray-Ban Meta's smart glasses were adding new social features, but the existing interaction model had been designed around simpler, single-purpose use cases. As the feature set grew, that model started to show its limits — particularly for people picking up the glasses for the first time, with no existing mental model for how a wearable device should respond to a social interaction. Meta brought in a SCADpro team to explore what the next generation of that interaction language could look like, working directly alongside Meta's own research and engineering teams over a twelve-week engagement.

Discovery

Early research made clear the problem wasn't one broken interaction — it was an assumption baked into the whole system. Synthesizing more than 5,000 data points across the team's existing research, the throughline was a mismatch in mental models: first-time users expected the glasses to behave like a phone notification, when the actual interaction was closer to a passive, ambient signal. That gap — not any single screen or gesture — was the real source of confusion.

Constraints

The engagement ran twelve weeks inside an academic semester, working alongside a live product team with its own roadmap — not a hypothetical timeline. Any concept had to work within the glasses' existing hardware: a small display, limited input methods, and real battery constraints. It also had to be explainable to a stakeholder audience in a single presentation, not rolled out gradually with room to course-correct.

Decisions

Two decisions did the most to shape the final direction — and each had a real alternative that didn't survive.

Considered and rejected

An early prototype mirrored phone-style notification patterns. It was dropped after testing showed it created the same "did I miss something" anxiety the project was trying to design away from.

Considered and rejected

A more flexible system offering multiple interaction styles per feature was considered, since it gave more room per use case. It was set aside because it multiplied what a first-time user had to learn — working against the goal of an interaction that needed no explanation.

Trade-offs

Committing to one core interaction pattern meant some proposed features didn't get a fully custom-tailored interaction of their own — they had to fit inside the same ambient model, even in places where a more specific gesture might have technically performed better in isolation. That was an intentional trade: consistency across the system mattered more than optimizing any single feature on its own.

Outcome

The interaction pattern was presented to stakeholders at Meta headquarters and was adopted as the team's default approach heading into their next release.

Retrospective

If I revisited this project today, I'd push earlier for a low-fidelity way to test the ambient-signal concept with real first-time users, rather than leaning as heavily on the team's existing research base before validating it independently. Twelve weeks is enough time to develop a strong point of view — it's not quite enough to fully close the loop on testing it, and that's the honest gap in this version of the work.

Deeper Look

Edge Cases & System States

An ambient interaction pattern has to account for a device that's frequently in a partially-attended state — glasses being worn but not actively looked at, low-battery states that shouldn't compete for the same ambient channel, and moments where more than one signal could plausibly fire at once.

Engineering Collaboration

Because the concept had to work within real hardware constraints, this stayed a close collaboration with Meta's engineering team throughout — testing what was actually perceivable given the display's limitations, not just what looked right in a static mockup.
